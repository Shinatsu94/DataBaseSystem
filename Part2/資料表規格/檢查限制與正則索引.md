# 檢查限制與正則表達式索引

> [返回資料表規格索引](資料表規格索引.md) | [返回專案總覽](../../README.md)

本文件集中列出教室租用系統中所有資料庫層級檢查與輸入層級正則表達式位置。資料庫層級限制由 MariaDB 在 `INSERT` 或 `UPDATE` 時執行；輸入層級正則則用於前端表單與後端 API，目的是在資料進入資料庫前先拒絕格式不合法的內容。

## 檢查方式分類

| 類型 | 執行位置 | 檢查效果 |
|---|---|---|
| `CHECK` | MariaDB 資料表 | 限制數值範圍、日期區間、節次順序、布林值及帳號格式。 |
| `REGEXP` | MariaDB `CHECK` 或 API 驗證 | 以正則表達式檢查文字格式，例如學號、教職員帳號、教室代碼、Email。 |
| `ENUM` | MariaDB 資料表 | 限制角色只能為 `student`、`teacher`、`admin`。 |
| `UNIQUE` | MariaDB 索引 | 防止 Email、節次名稱或狀態代碼重複。 |
| 外鍵 | MariaDB 資料表 | 確保子表資料必須參照既有主表資料。 |
| Trigger | MariaDB Trigger | 驗證角色權限、資料所有權、教室啟用狀態與時段衝突。 |

## 正則實作範圍說明

已直接寫入 MariaDB Schema 的正則檢查包含 `user_id`、`email`、`classroom_id`、`section_name`、`status_code` 與 `course_id`。例如 `email` 的格式不是只寫在文件中，而是由 `chk_users_email_format` 實作於 [`Part2/完整資料庫Schema.sql`](../完整資料庫Schema.sql#L64) 與 [`Part3/完整資料庫Schema.sql`](../../Part3/完整資料庫Schema.sql#L64)。

姓名、教室名稱、課程名稱、借用原因、審核意見與通知內容包含中文與常用標點。這類欄位在資料庫層使用 `CHAR_LENGTH(TRIM(...))` 檢查長度與空白內容，完整字元集合則由前端表單與後端 API 正則驗證，原因是 MariaDB 部署版本與字元集設定可能影響 Unicode 類別正則的相容性。

## 輸入層正則表達式位置

以下規則屬於表單與後端 API 的輸入驗證。資料庫已有 `CHECK`、`ENUM`、`UNIQUE`、外鍵或 Trigger 可保護的欄位，仍需在輸入層同步驗證，以便在使用者送出資料時即時提示錯誤原因。

### `users`

位置：[01_users.md - 嚴格值域與正則表達式限制](01_users.md#嚴格值域與正則表達式限制)

- `user_id`：`^([0-9]{8}|[a-z][0-9]{5,7})$`
- `username`：`^[\p{Han}A-Za-z·．・]{2,60}$`
- `email`：`^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,63}$`
- `role`：`^(student|teacher|admin)$`
- `department`：`^$|^[\p{Han}A-Za-z0-9（）()學院系所科中心處室組 -]{2,80}$`

### `classrooms`

位置：[02_classrooms.md - 嚴格值域與正則表達式限制](02_classrooms.md#嚴格值域與正則表達式限制)

- `classroom_id`：`^[A-Z]{3}[0-9]{4}$`
- `classroom_name`：`^[\p{Han}A-Za-z0-9（）()、 -]{2,80}$`
- `capacity`：`^(?:[1-9][0-9]{0,2}|1000)$`
- `is_active`：`^(TRUE|FALSE|true|false|1|0)$`

### `sections`

位置：[03_sections.md - 嚴格值域與正則表達式限制](03_sections.md#嚴格值域與正則表達式限制)

- `section_id`：`^(?:[1-9]|1[0-3])$`
- `section_name`：`^第 (?:[1-9]|1[0-3]) 節$`
- `start_time`：`^(?:[01][0-9]|2[0-3]):[0-5][0-9]:00$`
- `end_time`：`^(?:[01][0-9]|2[0-3]):[0-5][0-9]:00$`

### `booking_statuses`

位置：[04_booking_statuses.md - 嚴格值域與正則表達式限制](04_booking_statuses.md#嚴格值域與正則表達式限制)

- `status_id`：`^(?:[1-9]|10)$`
- `status_code`：`^(draft|pending|under_review|approved|rejected|canceled|expired|completed|suspended|resubmission_required)$`
- `status_name`：`^[\p{Han}A-Za-z0-9]{2,20}$`

### `course_info`

位置：[05_course_info.md - 嚴格值域與正則表達式限制](05_course_info.md#嚴格值域與正則表達式限制)

- `course_id`：`^[0-9]{8}$`
- `academic_year`：`^[1-9][0-9]{0,2}$`
- `semester`：`^[12]$`
- `course_name`：`^[\p{Han}A-Za-z0-9（）()、:：/\- ]{2,120}$`
- `teacher_id`：`^([0-9]{8}|[a-z][0-9]{5,7})$`

### `course_times`

位置：[06_course_times.md - 嚴格值域與正則表達式限制](06_course_times.md#嚴格值域與正則表達式限制)

```sql
SHOW CREATE TABLE users;
SHOW CREATE TABLE classrooms;
SHOW CREATE TABLE sections;

SHOW CREATE TABLE course_times;
SHOW CREATE TABLE long_term_bookings;

```

可使用下列指令檢查 Trigger 是否存在：

```sql
SHOW TRIGGERS FROM classroom_rental;
```

可使用下列測試確認 `chk_users_id_format` 的大小寫檢查是否生效：

```sql
-- 應失敗：教職員帳號首字母不可為大寫。
INSERT INTO users (user_id, username, email, role, department)
VALUES ('T13005', '測試教師', 'invalid.teacher@example.edu.tw', 'teacher', '資訊工程系');

-- 應失敗：Email 格式不完整，會被 chk_users_email_format 拒絕。
INSERT INTO users (user_id, username, email, role, department)
VALUES ('t13005', '測試教師', 'invalid.teacher', 'teacher', '資訊工程系');

-- 應成功：教職員帳號首字母必須為小寫。
INSERT INTO users (user_id, username, email, role, department)
VALUES ('t13005', '測試教師', 'valid.teacher@example.edu.tw', 'teacher', '資訊工程系');
```
