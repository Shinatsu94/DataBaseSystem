## 應用情境與使用案例
- 表定課表需要長期借用指定教室。
- 老師臨時調課需要進行異動。
- 學生與指導教授開會需要暫時借用教室。
- 班級開班會需要借用教室。
- 課程考試需要另外借用考場。

## 系統需求說明

### 功能性需求
- 教室預約申請: 使用者透過系統申請使用教室，等待管理員審核。
- 教室借用狀態: 可以查詢該教室的當前狀態(是否有人借用? 借用單位? 開放預約?)。
- 預約申請審核: 管理員可以透過該系統進行教室借用審核，是否通過或是駁回。
- 申請狀態通知: 是否通過審核、有待審核申請，會分別通知申請人或管理員。
- 長期借用匯入: 每學期開始前，管理員必需人工核對各教室課表資訊是否正確。
- 歷史紀錄查詢: 可以查詢個人的借用紀錄，管理員可以匯出指定條件的所有借用紀錄。

### 非功能性需求
- 身分驗證與權限控管: 系統需要能夠區分使用者類型與管理員，並給予對應的餐操作介面
- 預約防呆衝突機制: 在使用者送出教室預約，及時檢查該時段是否可借用


## 實體完整性限制
- 預約實體　　: 預約ID為主鍵，不能有空值。
- 教室實體　　: 教室ID為主鍵，不能有空值。
- 可借用時段實體: 
- 活動資訊實體: 活動資訊ID為主鍵，不能有空值。
- 時段實體　　: 時段ID為主鍵，不能有空值。
- 用戶實體　　: 用戶ID為主鍵，不能有空值。
- 長期借用實體: 長期借用ID為主鍵，不能有空值。
- 審核狀態實體: 審核狀態ID為主鍵，不能有空值。
