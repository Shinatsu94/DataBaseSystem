## 應用情境與使用案例

- 表定課表需要長期借用指定教室。
- 教師臨時調課時，需要異動教室使用安排。
- 學生與指導教授進行會議時，需要申請臨時借用教室。
- 班級舉辦班會或活動時，需要申請借用教室。
- 課程考試期間，需要另外申請考場。

## 系統需求說明

### 功能性需求

- 教室預約申請：使用者透過系統提出教室借用申請，並等待管理員審核。
- 教室借用狀態查詢：系統提供教室使用狀態、借用單位與可預約狀態之查詢功能。
- 預約申請審核：管理員透過系統核准或拒絕教室借用申請。
- 申請狀態通知：系統將審核結果通知申請人，並將待審核案件通知管理員。
- 長期借用匯入：每學期開始前，管理員應核對各教室之固定課表資訊。
- 歷史紀錄查詢：使用者得查詢個人借用紀錄；管理員得依指定條件匯出借用紀錄。

### 非功能性需求

- 身分驗證與權限控管：系統應區分學生、教師與管理員，並提供對應之操作權限。
- 預約衝突檢查：系統應於使用者送出教室預約時，驗證該時段是否得以借用。

## 核心資料表

| 資料表 | 用途 |
| --- | --- |
| `users` | 保存學生、教師與管理員資料 |
| `classrooms` | 保存教室基本資料與啟用狀態 |
| `sections` | 保存學校節次與起訖時間 |
| `booking_statuses` | 保存預約審核狀態 |
| `course_info` | 保存學期課程資訊 |
| `course_times` | 保存固定課表安排 |
| `long_term_bookings` | 保存長期借用計畫 |
| `bookings` | 保存單次預約紀錄 |
| `booking_reviews` | 保存管理員審核歷程 |
| `notifications` | 保存申請狀態通知 |

## 完整性限制

- 每個資料表皆以主鍵維持實體完整性。
- 外鍵必須參照至已存在之父資料，以維持參照完整性。
- `CHECK` 限制用於驗證角色、狀態、日期、節次與教室容量。
- 觸發器用於阻擋固定課表與已核准預約之時段衝突。
