# 教室租用系統：實體資料表格

本資料夾將 [`schema.sql`](../schema.sql) 的 10 個實體分別整理為獨立文件。每份文件皆包含用途、欄位表格、關聯實體、Domain 選擇、對應 View、呼叫語法與其他邏輯規則。

每份文件均內嵌該實體之局部 Mermaid 關聯圖，並針對每一項關聯提供意義與使用範例，以降低單一大型圖表之閱讀負擔。

完整專案入口位於 [`專案總覽.md`](../專案總覽.md)。角色權限、10 個 View、型態與時間精度位於 [`權限與View設計.md`](../權限與View設計.md)。

## 完整性分類

| 類型 | 說明 |
|---|---|
| 實體完整性 | 每個資料表皆有主鍵，主鍵不可重複且不可為空值。 |
| 參照完整性 | 外鍵必須對應至已存在的父資料，例如預約申請人必須存在於 `users`。 |
| 域值完整性 | 使用 `NOT NULL`、`UNIQUE`、`DEFAULT` 與 `CHECK` 限制可接受的值。 |
| 商業規則完整性 | 使用 Trigger 阻擋固定課表與已核准預約的時段衝突。 |

## 文件閱讀方式

每份實體文件均採用相同結構：

| 區段 | 說明 |
|---|---|
| 用途 | 說明實體在系統中保存之資料與負責之功能。 |
| 欄位表格 | 列出欄位名稱、資料型別、必填狀態、鍵值、預設值、完整性限制與欄位意義。 |
| 關聯實體 | 列出父實體、子實體、外鍵方向與 `1:N` 關聯。 |

| 使用範例 | 逐一說明每項關聯於教室租用情境中的實際用途。 |
| 其他邏輯規則 | 說明欄位值域、應用程式層驗證、時段衝突與歷程保存規則。 |
| Domain 與時間型別 | 說明為何使用 `CHAR`、`ENUM`、數值、`TEXT`、`DATE`、`TIME(0)` 或 `TIMESTAMP(6)`。 |
| 對應 View | 列出資料表對應 View、查詢語法與可見資料範圍。 |
