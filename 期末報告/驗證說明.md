# 教室租用系統：Schema 驗證說明

本文件記錄 [`schema.sql`](./schema.sql) 已完成之驗證情境、預期結果與保護機制。完整設計方法位於 [`Schema_設計說明.md`](./Schema_設計說明.md)。

## 實測環境

本 Schema 已於 `MariaDB 11.4.12` 完成實際執行驗證。測試環境以暫時容器建立資料庫，依序載入 [`schema.sql`](./schema.sql) 與 [`examples.sql`](./examples.sql)，完成後移除測試容器。

## 已驗證項目

| 測試情境 | 結果 | 保護機制 |
| --- | --- | --- |
| 建立合法使用者、教室與預約 | 接受 | Primary Key、Foreign Key |
| 預約引用不存在的教室 | 拒絕 | Foreign Key |
| 預約結束節次早於開始節次 | 拒絕 | Check Constraint |
| 同一教室的固定課表節次重疊 | 拒絕 | `course_times` Trigger |
| 核准預約與既有固定課表重疊 | 拒絕 | `bookings` 交叉檢查 Trigger |
| 同一教室的已核准預約重疊 | 拒絕 | `bookings` Trigger |
| 同一時段存在多筆待審核申請 | 接受 | 核准時再次執行衝突驗證 |

## 實測摘要

| 檢查項目 | 實測結果 |
|---|---|
| 建立資料表 | 成功建立 10 張資料表 |
| 建立觸發器 | 成功建立 4 個衝突驗證觸發器 |
| 載入範例資料 | 成功建立 1 筆預約與 1 則通知 |
| UTF-8 中文資料 | 成功保存教室名稱 `電腦教室 B205` |
| 不存在之教室外鍵 | MariaDB 拒絕寫入 |
| 結束節次早於開始節次 | MariaDB 拒絕寫入 |
| 已核准預約互相重疊 | Trigger 拒絕寫入 |
| 已核准預約與固定課表重疊 | Trigger 拒絕寫入 |
| 待審核案件與既有核准預約重疊 | 接受，留待核准時再次驗證 |

## 設計理由

待審核申請不會立即占用教室，因此得暫時並存。管理員將案件改為
`approved` 時，觸發器將再次比對固定課表與其他已核准預約。

此設計同時維持申請流程與資料一致性。

## 執行順序

```powershell
mariadb -u root -p -e "CREATE DATABASE IF NOT EXISTS classroom_rental CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
mariadb -u root -p classroom_rental < schema.sql
mariadb -u root -p classroom_rental < examples.sql
```
