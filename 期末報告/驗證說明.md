# 教室租用系統：Schema 驗證說明

本文件記錄 [`schema.sql`](./schema.sql)、[`views.sql`](./views.sql) 與 [`security.sql`](./security.sql) 的實際驗證結果。權限與時間型別依據位於 [`權限與View設計.md`](./權限與View設計.md)。

## 實測環境

本 Schema 已於 `MariaDB 11.4.12` 完成實際執行驗證。測試環境以乾淨容器建立資料庫，載入 Schema、範例資料、View 及角色權限，並以獨立學生、教師、管理員帳號執行正向與拒絕案例。

## 已驗證項目

| 測試情境 | 結果 | 保護機制 |
| --- | --- | --- |
| 建立合法使用者、教室與預約 | 接受 | Primary Key、Foreign Key |
| 預約引用不存在的教室 | 拒絕 | Foreign Key |
| 預約結束節次早於開始節次 | 拒絕 | Check Constraint |
| 同一教室的固定課表節次重疊 | 拒絕 | `course_times` Trigger |
| 核准預約與既有固定課表重疊 | 拒絕 | `bookings` 交叉檢查 Trigger |
| 同一教室的已核准預約重疊 | 拒絕 | `bookings` Trigger |
| 同一時段存在多筆待審核申請 | 接受 | 核准時再次執行衝突驗證 |
| 學生查詢 `users` 基礎資料表 | 拒絕 | 未授與資料表 `SELECT` |
| 學生查詢 `vw_users` | 僅顯示本人 | View 依 `USER()` 過濾 |
| 學生冒用其他申請人 | 拒絕 | `bookings` Trigger |
| 學生自行將案件改為 `approved` | 拒絕 | 狀態轉換 Trigger |
| 學生自行指定 `created_at` | 拒絕 | 欄位級 `INSERT` 權限 |
| 教師查詢課程 View | 接受 | 教師角色授權 |
| 教師建立自己的長期借用 | 接受 | View 與 Trigger |
| 教師替其他人建立長期借用 | 拒絕 | `long_term_bookings` Trigger |
| 管理員查詢全部 View 與基礎資料表 | 接受 | 管理員角色授權 |
| 審核人員不是管理員 | 拒絕 | `booking_reviews` Trigger |

## 實測摘要

| 檢查項目 | 實測結果 |
|---|---|
| 建立資料表 | 成功建立 10 張資料表 |
| 建立 View | 成功建立 10 個 View；`views.sql` 可獨立重建 |
| 建立觸發器 | 成功建立 10 個角色、權限與衝突驗證 Trigger |

| 時間精度 | `created_at` 實測為 `TIMESTAMP(6)`，保留 6 位小數秒 |

## 設計理由

待審核申請不會立即占用教室，因此得暫時並存。管理員將案件改為
`approved` 時，觸發器將再次比對固定課表與其他已核准預約。

此設計同時維持申請流程與資料一致性。

學生與教師透過 `SQL SECURITY DEFINER` View 存取資料，無須取得基礎資料表權限。View 使用登入帳號名稱對照 `users.user_id`；Trigger 負責阻止冒用申請人及不合法狀態轉換。

## 執行順序

```powershell
mariadb -u root -p -e "CREATE DATABASE IF NOT EXISTS classroom_rental CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
mariadb -u root -p classroom_rental < schema.sql
mariadb -u root -p classroom_rental < examples.sql
mariadb -u root -p classroom_rental < security.sql
```

若需單獨重建 View，應在 `security.sql` 之前執行：

```powershell
mariadb -u root -p classroom_rental < views.sql
```
