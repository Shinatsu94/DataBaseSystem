這次做「教室借用系統」的期末專題，真的讓我對資料庫有完全不一樣的體會。以前在寫 Python 或是 C++ 的時候，遇到各種邏輯判斷或是防呆機制，直覺就是用一大堆 if-else 包在程式碼裡面，總覺得資料庫就只是一個「把變數存起來的超大 Excel 檔案」而已。但這次從零開始把整個架構建起來，才發現根本不是這麼回事。<br>
一開始畫 ER 圖的時候其實蠻痛苦的。光是釐清「每週都有的正課」、「專題小組的長期借用」和「臨時借用一次」這三種狀況，大家就卡關很久。後來才搞懂，如果一開始沒有把 long_term_bookings 和單次 bookings 拆開，後面關聯起來絕對會是一場災難。這讓我學到一件事：如果資料庫的關聯沒切好，後面寫再多程式去補救都會很痛苦。<br>
真正開始用 MariaDB 寫 Schema 後，我才感受到 Primary Key、Foreign Key 和各種 Check 限制的威力。以前自己亂寫小專案可能資料表隨便開，型態也隨便設。這次加上了嚴格的限制，尤其是寫 Trigger（觸發器）的時候，我原本還在想「這種檢查寫在後端不就好了嗎？」直到親手在終端機打指令測試，看著系統直接跳出「Error: 預約撞期」的紅字，把違規的資料硬生生擋下來，那瞬間真的覺得有點感動！原來資料庫自己就能做這麼強大的防護，不用等程式碼來救。<br>
另外一個大收穫是學會用 View（檢視表）和權限控管。系統裡有老師、學生和管理員，如果直接把 Table 打開真的超危險。這次我們練習在資料庫端設定，讓學生帳號登入時只能撈到自己的單子，連偷看別人的機會都沒有，這比我在後端寫權限判斷還要安全又乾淨。<br>
這次專題把我這學期學到的正規化、關聯設計、Trigger 還有 View 全部串在一起了。雖然中間 Debug 處理那些連鎖報錯（像是匯入測試資料時一直被 Foreign Key 擋住）弄得有點崩潰，但看到最後系統能順利跑起來，並按照我們設定的規矩把不合理的預約擋掉，真的很有成就感。經過這次實戰，把這些底層的地基打通，對以後真的要串接前後端來寫完整的系統肯定超級有幫助。
